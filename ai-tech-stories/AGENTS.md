# Agent instructions: AI & Tech Stories

An independent storytelling studio inside `ai-tech-stories/`. It researches and
writes spoken stories about AI and tech history. It does **not** edit video.

## Scope

Work only inside this folder. Do not reach into the parent repository for voice
references, old scripts, prompt templates, pipelines, skills or databases — this
series builds its own identity from approved drafts, not from the existing content
project. Write all changes and generated metadata here.

Read `README.md`, `docs/CREATIVE_DIRECTION.md` and `docs/ASSET_RIGHTS.md` before
proposing changes.

**Workflow skill:** `.claude/skills/develop-story/SKILL.md` — source-backed story
packages.

## Video editing happens elsewhere

Editing the filmed result is **not part of this project**. The `edit-reel` skill at
the repository root cuts narrated footage transcript-first, pulling from Google
Drive and deciding the visuals from what was actually said. **Do not add a video
workflow here**, and do not write instructions describing one.

## Story principles

- First person when authentic. Natural language, real tension, rigorous sourcing.
- Niyi's face and voice stay at the centre, with meaningful historical and technical
  visuals around them.
- Never invent experiences, quotes, chronology or evidence.
- Do not drift into generic third-person documentary narration.
- **The filming script is a guide, not a contract.** He may improvise, paraphrase,
  reorder or add a genuine anecdote. Never ask him to submit a rewritten final
  script after recording — the recording is the record.

## Assets and honesty

- Require provenance and licensing for any external asset, sufficient for the
  platforms it will appear on.
- Clearly distinguish AI reconstructions from genuine archival material. Never
  present a generated image as evidence.
- Human approval before publishing.
- Keep source footage, rendered video, signed URLs, API keys and credentials out of
  Git.
- **Always state which automation actually exists and has been tested, versus what
  is still only proposed.** Do not describe planned capability as though it works.
